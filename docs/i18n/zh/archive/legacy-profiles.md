# v1 和 v1.1 配置

**历史规则：适用于主网 v2 H210537 之前。** v1 → v1.1 激活仍为 H95125，
v2 分叉不会重写过去区块的规则。

| 参数 | 历史值 |
| --- | --- |
| v1 → v1.1 | H95125 |
| Target interval | 20 s |
| ASERT | 6 blocks / 120 s |
| B25 | m22 / 25 pages |
| B255 | m24 / 255 pages |
| Live-input maximum | 1,020 |
| Subsidy | max(50 / 2^(log_slots − 24), 1) NOID |
| Terminal cap, v1 | 1 MiB |
| Terminal cap, v1.1 shared paths | 1,100,000 bytes |

页数不含主 coinbase，额外强制系统记录占一个有效页。矿工默认使用 B25。
第一次完成 B25 准备后，如果四倍耗时估计可满足 20 秒目标，就允许 B255，
之后按合格交易页数选择。这个自动许可规则不适用于 v2。

State 24–29 级的总奖励为 50、25、12.5、6.25、3.125、1.5625 NOID，
30–32 级最低为 1 NOID。扩容要求持续达到 75% 占用率。原分配期限为
4,730,400 个区块，每日名义间隔为 4,320 个区块。v2 根据新间隔保留从 genesis
起累计三年的目标时间期限，见[网络经济](../protocol/economics.md)。

历史区块上限为 256 个物理交易体、1,020 个活用户输入、510 个输出、1,530 个
操作，最多触及 256 个分段。编解码器仍需读取旧记录，其最大值不是当前 v2 准入预算。

旧 C1 计算给出 FRI 目标 128 位、Block–Tiwari 经典 FS-FRI 可证明与猜想值
均为 127 位、理想 QROM 半成功边界 64.707407428576 位，以及 Category 1
主导门深成本下界 173.391078499301 位。这些是不同的安全量，不能互换使用。
v2 祖先链的计算见[安全模型](../protocol/security-model.md)。
