# 故障排查

先查看准确的启动错误以及节点日志最后几行。多数故障都落在以下边界之一。

## CPU 不受支持

```text
CPU UNSUPPORTED
This CPU is too old or does not expose the required instructions.
REQUIRED x86-64 SSE4.1 + PCLMULQDQ
```

ARM64 要求 NEON 和 PMULL。发布版不会退回标量参考实现。

某些虚拟机套餐即使物理主机支持，也会隐藏 PCLMULQDQ。请检查虚拟机来宾系统
可见的 CPU 标志，或选择能够暴露所需指令的虚拟 CPU 配置。

2012 年后制造的大多数 Intel 和 AMD 桌面或服务器处理器都支持 SSE4.1
和 PCLMULQDQ，但虚拟机监控器必须把它们暴露给来宾系统。

运行不修改数据的检查：

```sh
parano1d --check-hardware
```

## 没有对等节点

检查：

```sh
parano1d-cli peers
```

确认出站 DNS 和 TCP 可用、本机时间正确、P2P 监听配置无误。若要接受入站
连接，请同时在主机和上游防火墙开放 TCP `9600`。

不要用开放 RPC `9601` 来代替 P2P。

## 挖矿按钮或进程不可用

挖矿需要：

- 节点已经完成同步；
- 一个经过认证的对等节点；
- 已就绪的内嵌 HistoryStep 运行时；
- 有效的奖励地址；
- CPU 支持所需指令。

运行：

```sh
parano1d-cli status
parano1d-cli peers
parano1d-cli mining
```

以 `--mode node` 启动的普通节点永远不会挖矿，即使旧 TOML 中包含
`mining.enabled = true`。

## 同步看似卡住

先判断节点正在验证区块头、验证终端证明、传输 State 分段，还是应用近期
后缀。这些阶段的 CPU、网络和磁盘特征不同。

在把高度不变视为数据损坏前，应尝试多个健康对等节点。中断的快照临时区
会在重启时自动丢弃。

## 导入后看不到地址余额

自动发现会在第一个空派生地址停止，并且最多检查 20 个候选地址。
如果旧钱包跳过了某个未使用索引，请显式生成后续地址。

收据是本地文件，导入密钥不会恢复它们。

## 发送被拒绝

常见原因：

- 交易周期（epoch）已变化；
- 某个输入被新区块花费；
- 活动地址发生变化；
- 输出槽位提示已经被占用；
- 费用报价低于当前策略；
- 扣除费用后余额不足；
- 选中的输入过多。

刷新钱包并重新构建交易意图。不要编辑序列化的交易意图字节；授权绑定完整
逻辑交易。

## 正常关闭需要时间

挖矿和证明任务会在安全取消边界停止。GUI 等待私有节点关闭网络并刷入
MDBX。全核工作时出现短暂延迟是正常的。

如果服务在配置的 timeout 后仍未停止，请先保存日志再强制终止。反复硬
杀进程会把普通延迟变成数据库恢复工作。

## 端口已被占用

找出占用 `9600` 或 `9601` 的进程。同一监听地址只能由一个节点绑定，
同一数据目录也只能由一个进程使用。

独立实例必须使用不同的监听端口和数据目录。GUI 管理的私有节点也可能与
使用默认值手动启动的 Core 冲突。

## 报告可复现故障

请提供：

- 发布版本和操作系统；
- CPU 型号及 `--check-hardware` 输出；
- 准确命令或 GUI 操作；
- 相关日志行；
- 节点当时是否同步、是否挖矿；
- 预期结果与实际结果。

绝不要提供 `wallet.key`、导出的主密钥、私密照片或 Bearer 令牌。

## 合约余额或日志缺失

连接同步节点后刷新，并检查相关已保存状态。调用可能将资金移至后继地址或
关闭实例。本地日志保存已留存及导入的证据；离线错过调用且区块体被裁剪后
可能出现空缺。通过 F7 Open file 导入另一方的合约回执，已有记录会保留。
仅导入主秘密不能恢复丢失的公开条款。参见[恢复](../contracts/receipts-and-recovery.md)。
