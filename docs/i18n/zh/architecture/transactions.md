# 交易架构

Parano1d 把区块携带的物理交易页与钱包授权的逻辑付款分离。

[`Tx8x2` 物理页](../reference/glossary.md#tx8x2)采用固定 323 字节编码，最多包含八个输入和两个输出。逻辑 [`PagedSpend`](../reference/glossary.md#pagedspend) 最多把 128 个物理页组合为一笔原子[交易意图](../reference/glossary.md#transaction-intent)，共用一个交易 ID 和一份[授权证明封装](../reference/glossary.md#authorization-envelope)。

| 层级 | 限制 | 用途 |
|---|---:|---|
| `Tx8x2` 物理页 | 8 个输入、2 个输出 | 固定的共识与证明记录 |
| `PagedSpend` | 128 页 | 一次原子钱包操作 |
| 逻辑交易 | 504 个输入及类别页预算 | 必须满足所选证明类别 |

## 固定物理页

每页包含共同的 `input_owner`、[交易周期（epoch）锚点](../reference/glossary.md#transaction-epoch-anchor)、手续费字段、八条输入记录、两条输出记录以及有效性位图（bitmap）。未启用记录必须是规范零值。

输入标识为：

```text
{slot_index, amount, creation_id}
```

输出标识为：

```text
{slot_index, amount, owner}
```

输出物化时，分配器提供新的 [`creation_id`](../reference/glossary.md#creation-id)。因此，即使数值槽位以后被复用，过期输入引用也不会重新变为有效。

## 一笔逻辑交易意图

第一页携带手续费和开始标记，最后一页携带结束标记。所有页面使用同一所有者与交易周期锚点，有效记录必须紧密排列。对于声明的输入和输出数量，页面数必须是最小值。

逻辑交易 ID 承诺：

- 协议版本；
- 页面数量；
- 按顺序排列的每个物理页哈希。

ID 由带域分离的 Poseidon2b 海绵函数计算。钱包授权绑定的是这个逻辑 ID，而非任何单页。

整组页面以原子方式准入、选择、证明和收录。矿工不能只选择一笔大型支出中手续费更有利的页面。

## 钱包构造

普通付款会花费[活动地址](../reference/glossary.md#active-address)对应所有者的输出。钱包优先选择较大金额，以减少证明输入数量；随后创建接收者输出，并把找零退回同一所有者。输出槽位来自节点提供的空槽位提示。

构造过程中有两条证明边界：

1. 钱包证明自己知道活动地址对应所有者的秘密；
2. 矿工证明输入当前存在、输出为空、数值守恒、手续费规则以及精确的转换后 State。

钱包证明在钱包状态锁之外生成。挖矿可以继续，但节点会优先处理本地交易，避免持续进行的矿工证明生成任务长时间阻塞用户操作。

## [内存池](../reference/glossary.md#mempool)准入

准入流程刻意在高成本证明验证前后重复低成本检查：

1. 解码规范的传输格式并验证整组语义；
2. 持有内存池锁时，检查手续费、交易周期、冲突与 [Live State](../reference/glossary.md#live-state)；
3. 释放锁，在有界 CPU 许可下验证授权证明封装；
4. 重新取得锁，再次执行低成本 Live State 与冲突检查；
5. 预留所有有效输入和输出槽，随后转发交易意图。

第二次低成本检查消除了授权验证期间新块或竞争交易造成的竞态。重复提交具有幂等性。

内存池最多容纳 1,024 笔逻辑交易以及 384 MiB 意图数据。槽位预留使输入与输出冲突检测保持常数时间。

## 区块选择

矿工按费率排列合格原子组，平局按交易 ID。Small 和 Large 遵守各自页限制及
共同的 504 个活输入、63 次调用、256 个分段限制。调用形成用户页前缀。
主 coinbase 单独计算，到期额外系统页减少一个用户页。
[类别选择](mining.md)由本地生产者决定，所有验证者按相同合约语义接受两类。

## 确认与收据

提交成功只表示本地节点接受并转发了完整交易意图，并不表示交易已被区块收录。交易收录并确认后，钱包才能从保留区块中恢复[收据](../reference/glossary.md#receipt)。

向同一所有者进行的归集不会生成收据。向任何不同所有者付款——包括同一钱包派生出的另一个非活动地址——都会作为支出凭证保留。

规范有效性规则见[交易协议](../protocol/transactions.md)，用户界面行为见[发送 NOID](../wallet/send.md)。

## 合约意图

合约意图携带公开程序及策略条款和一个调用页。钱包授权纳入高度选定的分支，
矿工证明 opening、程序及准确后继。两次准入检查都执行手续费、冲突和预算规则。
见[合约](../contracts/index.md)。
