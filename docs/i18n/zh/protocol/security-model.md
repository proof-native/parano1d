# 安全模型

工作量证明排序有效转换。递归证明建立有效性，不替代累积工作量分叉选择或
18 区块硬最终性边界。State 传输根据认证根检查，不因来自种子节点而被信任。

## 证明的内容

接受的终端覆盖精确输入实例、输出空槽、价值守恒、手续费、发行、合约策略及
整数程序转换、后 State 根和递归祖先链。普通输入需要所有者秘密；合约输入
需要由承诺策略和纳入高度选定的活跃授权。持有授权秘密不能绕过程序、分支权限或金额限制。

钱包证明绑定逻辑交易的秘密知识，矿工证明公开关系和父链接，节点验证并应用结果。
有效 nonce 无法修复无效证明。

## 分叉及矩阵边界

首个 v2 证明绑定所选的最后一个旧区块。认证来源属于特定边界和链，不是可信
检查点。重组必须更新所选来源，回滚孤块合约输出和回执；最终性限制保持不变。

过渡版本携带旧验证材料和新矩阵库。后续 retired-history 构建使用独立固定的
预处理密钥验证来源证书，可以省去旧矩阵字节。仍需两套 v2 矩阵、认证元数据和
来源证据。没有对应验证路径而直接删除文件不等于矩阵退役。

## 钱包、证据及网络边界

保护 256 位主秘密。知道秘密的人拥有同样支出权，但仍受相同合约策略限制。
共识无法区分持有相同秘密的所有者与攻击者。

合约条款和回执是单独公开数据。秘密不能从承诺哈希恢复丢失程序或错过的后继。
普通付款回执保存付款证据；合约 opening 还可能是花费必需材料。
见[合约恢复](../contracts/receipts-and-recovery.md)。

交易、金额、所有者和公开程序在可用时是透明的，第三方可归档。
零知识隐藏花费见证，不隐藏公共账本陈述。

节点 Ed25519 身份只认证传输。DNS 种子寻找节点，不能授权交易或定义链。
连接多样性、消息限制及分阶段同步约束资源使用。请保持所有者 RPC 本地访问，
保护钱包数据，并为基础设施使用独立连接。
