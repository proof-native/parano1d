# 网络经济模型

Parano1d 把发行量与 [Live State](../reference/glossary.md#live-state) 容量绑定，并将持久 State 增长与普通交易处理分别定价。

## 单位

```text
1 NOID = 1,000,000 μNOID
```

NOID 是币种代码；钱包界面中使用符号 ①。
所有共识金额都以 [μNOID](../reference/glossary.md#micronoid) 整数表示。

## 区块奖励

初始补贴为 50 NOID。每当 State 域扩展，补贴减半，但永不低于 1 NOID：

| `log_slots` | 容量 | 区块奖励 |
|---:|---:|---:|
| 24 | 16,777,216 个槽位 | 50.000000 NOID |
| 25 | 33,554,432 个槽位 | 25.000000 NOID |
| 26 | 67,108,864 个槽位 | 12.500000 NOID |
| 27 | 134,217,728 个槽位 | 6.250000 NOID |
| 28 | 268,435,456 个槽位 | 3.125000 NOID |
| 29 | 536,870,912 个槽位 | 1.562500 NOID |
| 30–32 | 最多 4,294,967,296 个槽位 | 1.000000 NOID |

扩展需要在具备硬最终性的窗口内持续达到 75% 占用率。因此，只有当前 State 容量已经得到实质使用时，网络才进入更低通胀档位。

## 网络初期开发分配

按 20 秒目标出块间隔折算的前三年内，每个区块补贴按以下比例分配：

- 90% 给矿工；
- 5% 给 O(1) Network Fund；
- 5% 给 Parano1d Lab。

没有预挖。高度 4,730,400 之后，全部区块补贴归矿工。

为避免每个区块额外创建两个未花费 UTXO，两份开发分配每 4,320 个目标区块通过一条强制双输出[系统记录](../reference/glossary.md#system-record)支付。金额采用付款边界处生效的奖励档位。若 State 在该区间内扩展，由此产生的差额保持未发行。

在初始 50 NOID 补贴档位，矿工每块获得 45 NOID 加可领取的手续费，每个基金每 4,320 个区块获得 10,800 NOID。计划共支付 1,095 次，最后一次位于高度 4,730,400。付款由区块高度决定，不保证实际日历时间。

付款计划、接收者和金额仅由高度与 `log_slots` 无状态地推导，并在 `HistoryStep` 内证明。矿工不能遗漏付款、修改收款方或推迟到期付款。

## 手续费

最低交易手续费包括：

- 每笔逻辑交易 5,000 μNOID；
- 每个有效输入 100 μNOID；
- 每个有效输出 700 μNOID；
- 每个净新增已占用槽位 2,500 μNOID，再乘以占用压力倍数。

压力倍数为：

| 父 State 占用率 | 倍数 |
|---:|---:|
| 低于 50% | 1× |
| 50% 至低于 75% | 2× |
| 75% 至低于 90% | 4× |
| 90% 及以上 | 8× |

[State 增长费](../reference/glossary.md#state-growth-fee)会被销毁。基础费、输入费、输出费以及自愿追加的手续费可由矿工领取。

把多个输入归集为一个输出会缩减 State，因此不支付 State 增长费。

## 动态转发下限

共识手续费与本地转发策略相互独立。动态下限取 5,000 μNOID 与本地内存池最近接纳的 50 笔交易之中位手续费的 90% 两者中的较大值，不代表全网手续费估计。

只有出现压力时才启用较高下限。交易数量或保留字节数达到各自限制的 80% 即启用；两者都严格低于 50%，或内存池清空时，重置为默认值。两道阈值之间保留当前压力状态。现有的 1,024 笔交易和 384 MiB 限制不变。

本地转发下限上升本身不会驱逐已经接纳的交易。父 State 占用率导致共识最低手续费上升则不同，正常的新区块清理会移除不再满足该最低值的交易，并释放其本地预留。

钱包 Auto 根据实际交易形状、当前父 State 占用率与本地转发下限计算手续费。接纳之前收到本地手续费拒绝时，Auto 可在现有三次提交尝试内重新规划。手动手续费与用户已确认的归集报价不会被自动提高。不增加对等节点手续费轮询，也不承诺在其他节点的任意策略下都能确认。
