# 网络经济模型

v2 将两项职责分开：**区块高度决定发行，活 State 占用率决定持久存储成本**。
本页规则从 **H210537** 起适用。下文解释为何改变原模型，旧网络配置保存在
[归档](../archive/index.md)中。

## 单位

```text
1 NOID = 1,000,000 μNOID
```

代号为 NOID，钱包符号为 ①。共识使用整数 μNOID，不使用浮点运算。
由于永久尾部补贴持续为每块 1 NOID，因此没有固定最大供应量。

## v2 发行

令 `H = 210537`、`I = 1051200`。对于高度 `h ≥ H`，档位为
`min((h − H) / I, 8)`，采用整数除法。准确总补贴表如下：

| 档位 / v2 起名义年数 | 首个高度 | 每块 NOID | 每完整间隔总补贴 NOID |
| ---: | ---: | ---: | ---: |
| 0 | 210,537 | 16 | 16,819,200 |
| 1 | 1,261,737 | 11.30 | 11,878,560 |
| 2 | 2,312,937 | 8 | 8,409,600 |
| 3 | 3,364,137 | 5.65 | 5,939,280 |
| 4 | 4,415,337 | 4 | 4,204,800 |
| 5 | 5,466,537 | 2.83 | 2,974,896 |
| 6 | 6,517,737 | 2 | 2,102,400 |
| 7 | 7,568,937 | 1.41 | 1,482,192 |
| 8 | 8,620,137 | 1 | 1,051,200 |

最后一行无限重复。九个金额是准确共识常量：
**16 → 11.30 → 8 → 5.65 → 4 → 2.83 → 2 → 1.41 → 1**。
边界处不计算平方根，也不进行人工调整。区块关系证明由认证高度选择的奖励。
State 扩容不会提前或重置此计划。

在 **30 秒目标**下，一个间隔为名义上的 365 天。实际日期取决于出块速度；
计时从 v2 区块开始，不从 genesis 或发布日期开始。八个递减间隔的总计划补贴为
**53,810,928 NOID**，前两个为 **28,697,760 NOID**，尾部为
**每名义年 1,051,200 NOID**。这些是补贴之和，不是流通供应预测；销毁、
未领取金额及临时分配记账影响实际发行和活价值。

## 为什么更改货币时钟

初始模型将奖励下降与 State 扩容绑定：从 50 NOID 开始，当持续占用需要更大
槽位域时减半。它假设有用网络活动的增长能够为发行下降提供有意义的时钟。

主网早期运行暴露了差异：活占用率保持较低，而区块持续按初始档位发行。
State 衡量的是**当前活输出**，不是经过的时间、交易量或采用程度。花费释放
槽位，合并减少输出数量，合约可以反复更新一个权利而不增加活集合。
高效、繁忙的应用也可能几乎不改变 State 大小。因此仅由扩容触发的下降没有
可预测期限，节约 State 不应使未来发行更难理解。

v2 用经过认证的高度替代依赖活动的货币时钟。新计划从公布的分叉高度开始。运营者可检查准确常量，应用无需
预测占用率就能计算任何未来档位。现有余额不会重新缩放。

## 为什么选择这条曲线

设计选择永久 **1 NOID 尾部**、到达尾部前**四次等效减半**，以及
**每次减半两个名义年**。这给出八年内 `16 → 8 → 4 → 2 → 1` 的锚点。
每次减半分成两次年度下降，对应约 `1/√2` 的乘数，中间值固定为整数金额。

尾部使区块补贴与手续费长期并存；有限过渡提供清晰期限，较小的年度步骤将
后续补贴下降分散，而非每个边界一次下降 50%。中间档位取整为固定金额 11.30、5.65、2.83 和 1.41 NOID。

从每 20 秒 50 NOID 转为每 30 秒 16 NOID，在各自目标速度且旧 State 未减半
的前提下，初始总发行速率降低 **78.67%**。这是一次显著的初始下降，随后执行
计划步骤。高度规则无需再按观察到的 State 增长调节货币时钟；未来再改变需要另一次共识升级。

## State 效率仍有经济意义

合并的经济动力保留。每个 State 级别内部，占用率提高会提高**净新增活槽位**
的价格，该增长部分全部销毁。将多个输入合并成更少输出可释放槽位并避免增长费，
但仍需支付普通输入输出费。合约按同样规则支付实际活占用成本。
发行与存储定价分别解决各自问题，不妨碍高效复用 State。

## 现有分配计划

90% / 5% / 5% 的补贴分配继续覆盖从 genesis 起累计三个 365 天目标时间年。
v2 不重新启动期限。扣除增长销毁后的手续费仍可由矿工领取。

剩余目标时间换算为 30 秒区块：
`H − 1 + floor((94608000 − (H − 1) × 20) / 30) = 3223778`。
分配在 **H3223778** 结束，此后补贴全部归矿工。v2 名义每日结算间隔为
**2,880 个区块**，首次为 **H213416**。H210537 不结算，旧周期未完成部分不支付。
v2 最后一个不完整周期在结束高度结算，比例和收款人不变。

结算使用边界处奖励档位，间隔内档位变化可能使差额不发行。初始 16 NOID 档位
的矿工补贴为 14.4 NOID，每个完整日间隔的 5% 份额为 2,304 NOID。
强制系统记录由共识推导，不由运营者提交。这是总补贴内部分配，不是额外发行。

## 手续费

最低交易手续费包括：

- 每笔逻辑交易 5,000 μNOID；
- 每个有效输入 100 μNOID；
- 每个有效输出 700 μNOID；
- 每个净新增已占用槽位 2,500 μNOID，再乘以占用压力倍数。

压力倍数为：

| 父 State 占用率 | 倍数 |
|---:|---:|
| 低于 50% | 1× |
| 50% 至低于 75% | 2× |
| 75% 至低于 90% | 4× |
| 90% 及以上 | 8× |

[State 增长费](../reference/glossary.md#state-growth-fee)会被销毁。基础费、输入费、输出费以及自愿追加的手续费可由矿工领取。

把多个输入归集为一个输出会缩减 State，因此不支付 State 增长费。

## 动态转发下限

共识手续费与本地转发策略相互独立。动态下限取 5,000 μNOID 与本地内存池最近接纳的 50 笔交易之中位手续费的 90% 两者中的较大值，不代表全网手续费估计。

只有出现压力时才启用较高下限。交易数量或保留字节数达到各自限制的 80% 即启用；两者都严格低于 50%，或内存池清空时，重置为默认值。两道阈值之间保留当前压力状态。现有的 1,024 笔交易和 384 MiB 限制不变。

本地转发下限上升本身不会驱逐已经接纳的交易。父 State 占用率导致共识最低手续费上升则不同，正常的新区块清理会移除不再满足该最低值的交易，并释放其本地预留。

钱包 Auto 根据实际交易形状、当前父 State 占用率与本地转发下限计算手续费。接纳之前收到本地手续费拒绝时，Auto 可在现有三次提交尝试内重新规划。手动手续费与用户已确认的归集报价不会被自动提高。不增加对等节点手续费轮询，也不承诺在其他节点的任意策略下都能确认。
